## 0. 先检查当前代码与风险

目前仓库可读取的关键接口：

```text
src/bearing_agents/domain/state.py            DesignState.task_plan
src/bearing_agents/domain/agent_protocols.py  TaskRecord, PlanDecision, AgentResult, StatePatch
src/bearing_agents/domain/enums.py            TaskStatus, PrecheckStatus, SimulationStatus
src/bearing_agents/domain/proposals.py        ParameterChangeProposal / Resolution
src/bearing_agents/domain/write_context.py    WriteContext / WriterKind
src/bearing_agents/domain/events.py           StateEvent
src/bearing_agents/core/state_manager.py      StateManager.apply_patch 等现有接口
src/bearing_agents/core/dependency_tracker.py invalidate_dependents
pyproject.toml                                当前只含 pydantic 运行依赖
```

**第一项实际冲突**：`TaskRecord.dependencies` 当前被 `DependencyTracker` 作为输入字段依赖。如果把它当任务 ID，失效判断将出错；本 PR 先冻结 `depends_on_task_ids`（任务拓扑）与 `consumed_input_refs`（输入依赖）两个语义，提供兼容迁移测试，**不要混用 legacy 字段**。在 PR-07 前若无法做到精确依赖，宁可保守失效。

**第二项当前前提**：现有 StateManager 对确认、角色、候选和来源有权限约束。只允许小幅扩展适配；不允许为了 Graph 写一套新的 `DesignState`/`StateManager`/业务数据库。

## 1. 三个内部实施检查点（仍是同一个 PR）

### 02-C0：协议冻结与迁移

1. 读取当前 main 和 PR-01 测试，形成不超过一页的差异计划；明确选定的 LangGraph 与 checkpoint 后端依赖版本。
2. 实现或复用 `ActionSpec`, `GuardDecision`；保留已有 `PlanDecision`、`AgentResult` 字段，不破坏 `extra='forbid'` 的反序列化。
3. 明确 `depends_on_task_ids` / `consumed_input_refs` / legacy `dependencies` 的语义与兼容路径；开发相应迁移/边界测试。
4. 冻结用户交互六类事件的**语义/信封规范**，本 PR 只提供可信离线用户模拟器和确认/拒绝的恢复测试，不开发完整聊天事件系统。
5. 固化 `PrecheckStatus` 与 `SimulationStatus` 各自含义；仿真能力返回 NOT_AVAILABLE，不伪造任务或专业结果。
6. 全量 PR-01 回归通过，才能推进 02-RUNTIME。

**C0 验收**：旧设计 JSON 能合法读取或有明确失败/迁移处理；字段依赖和任务拓扑不会被同一 `list[str]` 混用；Agent 自称 USER/CONFIRMED 不生效。

### 02-RUNTIME：可测试的 LangGraph 动态路由

建议节点 `observe_state` → `plan_next` → `policy_guard` → `dispatch_agent` → `validate_result` → `trusted_commit` → `observe_state`，在 Guard/进展检查出路由至 `wait_user` 或 `finish`。

- `GraphState` 持有 `design_id`, `thread_id`, `observed_state_version`, `current_goal`, `current_task_id`, `plan_revision`, `last_decision_ref`, `last_result_ref`, `replan_count`, `termination_reason`；不复制参数、约束或候选数据的可写快照。
- `StateObserver` 从现有 StateManager 读取一个小型 StateSummary，包括输入门槛、现有候选、未解 issues、待确认对象、可用动作、剩余循环预算。状态摘要不得混入“已审核规则”与“草案条款”。
- `FakePlanner` 实现 `Planner` 协议且确实根据状态不同给出不同动作；它不可直接写 StateManager。至少区分缺输入/已 R2/已有候选/确认中断/仿真不可用。图节点可能固定，专业动作必须动态选择。
- `ActionCatalog` 是合法动作与执行者映射；`PolicyGuard` 审核 action、expected schema、状态版本、前置条件、权限和当前工具是否可用。
- `Dispatcher` 只能调用经 Guard ALLOW 的 FakeAgent/确定性工具；`AgentResult` 经 schema/任务 ID/目标版本校验。`ResultValidator` 不能信任模型自报 `confirmed_by`、`source=user`、`actor`。
- `TrustedCommitter` 只使用可信的 `WriteContext` 调 StateManager，领域事件和参数只在其可信存储中维护。
- 调度循环必须有退出原因：`GOAL_REACHED`, `WAITING_FOR_USER`, `MISSING_INPUT`, `UNSUPPORTED_ACTION`, `NO_PROGRESS`, `RETRY_BUDGET_EXHAUSTED`, `UNEXPECTED_ERROR`（执行原因码，不要求扩展 Domain enums）。

**RUNTIME 验收**：同一个 Graph 入口面对缺载荷和 R2 就绪输入会走不同动作；不创建 `PRECHECK_PASS`/虚构仿真；无真实模型 API 也能运行。保留行动 trace：`state_version → action → guard → task/agent → commit_version → next/stop`。

### 02-RECOVERY：持久化、幂等和中断

- 选择可持久化的 checkpointer（可将 SQLite 作为开发持久后端），与 PR-01 工程 SQLite 可以物理同服务器，但**不假设 Graph checkpoint 和领域业务写入处于同一事务**。内存型 saver 仅用于单元测试，不得作为“重启恢复成功”证据。
- 每个有领域副作用的操作使用在恢复重试中**不变化**的 `operation_id`；域写入事务使用唯一约束/幂等结果记录加版本 CAS，确保重复调用不重复产生候选、确认、版本和审计事件。
- 恢复时总是先读最新领域版本和 operation 结果；已完成的副作用返回已记录结果，未完成的执行可继续/重规划。
- `interrupt()` 只传 JSON 可序列化的确认请求摘要；Node 恢复时重新审查目标版本及依赖；过期确认不可提交。不要在 interrupt 前执行不受幂等保护的 append 或新对象创建。
- 默认单会话串行领域写入；遇到两个同时执行的 Graph 线程，以 state_version/CAS 明确拒绝并提示刷新，不做并行编排优化。

**RECOVERY 验收**：故意让数据库写入完成而 checkpoint 更新失败，恢复后提交次数仍为一；同一用户批准重复 resume 只产生一次确认效果；等待期间目标变动则旧确认失效并返回清晰原因。

## 4. `operation_id` 和提交策略详细约定

- `operation_id` 必须绑定稳定逻辑任务与其**目标效果意图**，如 `design_id / task_id / effect_kind / target_artifact_id+version`，不要包含每次重试生成的新 UUID。
- 若操作意图发生实质改变（不同候选、新的用户确认对象），必须创建**新的** operation_id；不能错误地把两个不同批准当作同一操作去重。
- 域事务执行：查 operation 是否已提交 → 若是返回以前的结果引用 → 否则检查 CAS + PolicyGuard 证明 → 执行受信变更 → 保存业务结果、事件和 operation 记录 → commit。
- 业务提交可能成功但 Graph checkpoint 失败是**被允许的故障**；系统应安全恢复。只承诺“至少一次节点执行 + 业务效果幂等”，不声称跨库 exactly-once。

## 5. 验收前严禁引入的复杂性

- 真实 LLMPlanner、真实 Requirements/Design/Validation Agent Prompt、ISO 标准条款检索或数值表。
- 通用 DAG 优化调度、复杂任务并行执行、微服务消息队列或自行重写 LangGraph checkpoint。
- 将 `GraphState` 设计成另一份可写工程状态，或让模型传入 `WriteContext(USER)`。
- 靠“主动调用 FakeAgent 直到它给 SUCCESS”伪造进度；所有状态更新必须能从现有领域事实和事件轨迹解释。
- 当前 PR 内设计真实膜厚/温度/局部压力计算，也不允许伪造仿真适配返回值。
