# 滑动轴承多智能体系统框架规划

## 1. 文档定位

本文是本课题第一版多智能体系统的框架设计。系统面向轴承设计经验不足、不能一次性说清全部条件的设计人员，目标不是替用户简单查询一个轴承型号，而是引导用户逐步完成一次**滑动轴承应用设计分析**。

首期系统采用六个逻辑 Agent：

```text
1. 总控导师 Agent
2. 需求与工况 Agent
3. 滑动轴承应用设计 Agent
4. 分析规划 Agent
5. 计算 Agent
6. 结果校核与解释 Agent
```

第一版不单独设置优化 Agent。计算结果不满足时，由总控导师根据失败类型把任务送回需求、分析规划或应用设计阶段；应用设计 Agent 进入“设计修改模式”，创建新版本后重新分析。

## 2. 系统目标

### 2.1 用户目标

用户可以从类似下面的模糊需求开始：

```text
我要给某设备设计一个低速重载滑动轴承。
```

系统需要逐步帮助用户完成：

```text
设计目标理解
→ 工况和约束补充
→ 滑动轴承应用方案形成
→ 用户确认设计方案
→ 分析类型和计算设置确定
→ 调用 DLAP 或其他已验证计算程序
→ 结果校核和解释
→ 用户选择修改方向
→ 新版本重新分析
→ 设计说明和计算报告
```

### 2.2 系统不是以下几类工具

- 不是只根据数据库返回一个轴承型号的查询器；
- 不是让多个大模型自由讨论、最后自行决定结果的聊天系统；
- 不是由大模型直接拼接命令行和计算输入的脚本；
- 不是替代有资质设计人员进行最终工程审批的系统；
- 不是首期就覆盖所有滑动轴承、瞬态、有限元和复杂轴系的完整 CAE 平台。

## 3. 首期范围

### 3.1 推荐黄金路径

为了先跑通完整闭环，首期建议固定一条可验证路线：

```text
圆柱径向滑动轴承
→ 稳态或准稳态工况
→ 单一工作点
→ 已知载荷和转速
→ 已知或可查询的润滑剂
→ 采用确定的材料和几何参数
→ 调用 DLAP 进行基础分析
→ 校核油膜、压力、温度和流量等指标
```

系统架构保留推力轴承、静压轴承和多工况扩展接口，但它们不作为首期黄金路径的完成条件。

### 3.2 首期支持的设计深度

首期做滑动轴承**应用设计**，包括：

- 轴承应用场景和工况理解；
- 径向/推力路线判断；
- 轴承几何参数和设计变量的组织；
- 材料与润滑剂候选；
- 间隙、长径比、供油方式等设计参数的确认或建议；
- 分析模型和计算设置选择；
- DLAP 输入转换和运行；
- 结果规则校核；
- 失败后的设计修改和版本迭代。

首期不承诺：

- 自动完成完整轴系受力分析；
- 自动完成瞬态启动、停机和复杂载荷谱；
- 自动完成三维结构、二维工程图和制造工艺；
- 自动完成有限元、流固耦合或多体动力学；
- 在没有验证工具协议时声称 DLAP 结果已具备正式工程证据等级。

### 3.3 首期校核指标

先选择少量可以取得可靠结果的指标，建议包括：

```text
最小油膜厚度
最大压力或比压
最高温度和温升
供油流量
摩擦功耗
是否存在接触或油膜破坏风险
```

具体指标是否启用由分析规划 Agent 根据工况和工具能力确定。标准、企业规则或专家经验未确认时，结果必须标记为 `unknown`，不能默认为通过。

## 4. 核心设计原则

### 4.1 渐进式交互

系统不要求用户第一轮填写完整参数表。每轮只询问当前设计阶段最重要的问题，并显示：

- 当前已经知道什么；
- 仍然缺少什么；
- 为什么需要该信息；
- 用户可以从哪里获得该信息；
- 缺失信息是否阻断下一步。

### 4.2 默认简单，按需加深

一般用户只需要先回答载荷、转速、温度、润滑和目标等基础问题。接触、紊流、热边界、油腔、轴向结构等专业设置只有在当前工况或分析任务确实需要时才出现。

### 4.3 Agent 只提案，工程服务做判断

Agent 负责理解、提问、提出设计建议和解释结果；确定性程序负责：

- 状态和版本；
- 参数完整性、单位和范围检查；
- 规则数值比较；
- 计算输入转换；
- DLAP 调用和输出解析；
- 结果失效和依赖追踪。

### 4.4 用户确认不能被模型代替

以下内容必须展示给用户确认，不能由 Agent 静默决定：

- 设计路线；
- 关键几何参数；
- 材料和润滑剂选择；
- 热边界和模型开关；
- 设计目标和优化优先级；
- 通用标准与企业规则冲突时的采用依据。

### 4.5 结果必须可追溯

每次结果必须绑定：

```text
设计任务
设计版本
参数快照
分析计划版本
规则版本
适配器版本
DLAP 版本
输入和输出工件
日志和退出状态
```

## 5. 六个 Agent 的详细职责

## 5.1 总控导师 Agent

### 核心问题

```text
用户当前处于哪个设计阶段？下一步应该让哪个模块工作？
```

### 输入

- 用户消息；
- 当前 `DesignState`；
- 当前设计版本；
- 状态机允许的动作；
- 其他 Agent 的结构化结果；
- 阻断原因、待确认项和工具状态。

### 职责

- 识别用户是在补充条件、确认方案、修改设计还是询问结果；
- 调用需求、应用设计、分析规划、计算和结果校核 Agent；
- 合并不同 Agent 的问题，避免重复提问；
- 控制每轮问题数量，优先展示阻断项；
- 在用户不理解术语时进行解释；
- 控制需求确认、设计方案确认和分析计划确认；
- 根据失败类型决定回到哪个阶段；
- 在超范围、冲突或证据不足时转专家确认。

### 输出

```json
{
  "action": "ask_user",
  "stage": "analysis_plan_confirmation",
  "message": "当前低速重载工况建议开启接触风险检查，并重点校核最小油膜厚度。是否按此方案继续？",
  "questions": [],
  "requires_confirmation": true,
  "target_agent": "analysis_planning",
  "blocking_reasons": []
}
```

### 禁止事项

- 不直接修改 `DesignState`；
- 不直接判断数值是否通过；
- 不绕过确认门调用计算；
- 不把自然语言猜测写成工程事实；
- 不让 Agent 无限循环调用其他 Agent。

## 5.2 需求与工况 Agent

### 核心问题

```text
用户要设计什么？使用条件是什么？目标和限制是什么？
```

### 需要逐步了解的内容

| 类别     | 示例字段                           | 首期处理                   |
| -------- | ---------------------------------- | -------------------------- |
| 设计对象 | 设备、轴段、轴承位置               | 必须理解                   |
| 任务类型 | 新设计、替换、已有方案校核         | 必须确认                   |
| 轴承路线 | 径向、推力、暂不确定               | 作为路线输入               |
| 载荷     | 大小、方向、是否稳态、变化情况     | 基本工况                   |
| 转速     | 最低、常用、最高或单一转速         | 基本工况                   |
| 几何     | 轴径、轴承宽度、直径、间隙等       | 已知则记录，缺失按阶段补充 |
| 润滑     | 供油方式、油品、黏度、温度         | 按当前分析需要提问         |
| 材料     | 轴瓦材料、基体、涂层或企业限制     | 需要时提问                 |
| 环境     | 温度、粉尘、潮湿、腐蚀             | 影响适用性时提问           |
| 目标     | 油膜、温度、压力、流量、寿命、成本 | 必须形成优先级             |
| 约束     | 空间、材料、品牌、供油能力、维护   | 记录来源和版本             |

### 职责

- 从自然语言提取事实；
- 区分用户输入、系统建议、派生值、未知和歧义；
- 判断当前需求是否可以形成初步设计；
- 生成需求阶段的问题候选；
- 发现单位缺失、方向不清和参数矛盾；
- 解释“为什么需要某项信息”；
- 把“不知道”保留为明确状态，不强行补值。

### 输出

```json
{
  "design_brief": {
    "task_type": "new_design",
    "bearing_route": "journal_bearing",
    "application": "泵",
    "operating_mode": "continuous",
    "load": {
      "value": 12000,
      "unit": "N",
      "direction": "radial",
      "status": "user_provided"
    },
    "speed": {
      "value": 1500,
      "unit": "rpm",
      "status": "user_provided"
    },
    "unknowns": ["lubricant_viscosity", "clearance"],
    "constraints": [],
    "priorities": ["temperature", "minimum_film_thickness"]
  },
  "questions": [
    {
      "field": "lubrication.oil_temperature",
      "question": "进入轴承的润滑油大约是多少温度？如果暂时不知道，可以选择由系统采用假设。",
      "why_needed": "温度会影响润滑油黏度和温度计算",
      "blocking": true,
      "priority": 90
    }
  ],
  "can_form_design": true,
  "blocking_reasons": []
}
```

### 禁止事项

- 不决定最终几何参数；
- 不决定 DLAP 模型开关；
- 不把模糊描述直接换成默认数值而不告知用户；
- 不直接判断油膜和温度是否满足要求。

## 5.3 滑动轴承应用设计 Agent

### 核心问题

```text
根据当前需求，应该怎样构造这套滑动轴承应用方案？
```

### 输入

- 已确认或明确标记为假设的设计任务；
- 载荷、转速、温度和润滑条件；
- 几何和材料信息；
- 材料、润滑剂和企业经验检索结果；
- 设计目标和优先级；
- 当前支持的设计路线和工具能力。

### 职责

- 判断径向轴承、推力轴承、动压、静压等设计路线；
- 组织轴承几何、材料、润滑和供油方案；
- 提出间隙、长径比、供油方式等设计变量；
- 使用数据库和专家经验产生候选参数或初始值；
- 说明哪些参数可由系统建议，哪些必须由用户确认；
- 形成一个或多个可比较的应用设计方案；
- 识别当前方案的假设、风险和超范围内容；
- 根据校核失败结果进入“设计修改模式”。

### 与数据库的关系

数据库不是最终目标，而是设计依据之一。应用设计 Agent 可以查询：

- 材料数据库；
- 润滑剂数据库；
- 几何参数和经验范围；
- 企业允许的材料和润滑方式；
- 标准和专家经验规则。

数据库返回的是有来源的候选和约束，Agent 需要结合工况形成设计方案，不能直接把检索结果当成最终设计。

### 输出

```json
{
  "design_mode": "journal_hydrodynamic_application_design",
  "scheme_id": "DB-V1-S1",
  "geometry": {
    "journal_diameter_mm": 80,
    "bearing_width_mm": 80,
    "radial_clearance_um": 80
  },
  "material": {
    "candidate": "企业材料库中的材料 A",
    "evidence_refs": ["material-db-v1:A"]
  },
  "lubrication": {
    "method": "forced_oil",
    "candidate": "VG46",
    "evidence_refs": ["lubricant-db-v1:VG46"]
  },
  "design_targets": [
    "minimum_film_thickness",
    "maximum_temperature",
    "maximum_pressure"
  ],
  "assumptions": [],
  "alternatives": [],
  "unresolved_items": [],
  "requires_user_confirmation": true
}
```

### 交互方式

它可以提出设计决策问题，例如：

```text
当前计算得到的供油量可能较大。你更关注降低供油成本，还是优先保证较低温度？
```

它不要求用户使用专业术语，而是给出可解释的选项和影响。

### 禁止事项

- 不凭空生成材料性能或润滑油参数；
- 不把企业经验伪装成通用标准；
- 不绕过用户确认直接进入计算；
- 不把计算尚未验证的参数说成已满足要求。

## 5.4 分析规划 Agent

### 核心问题

```text
为了判断当前设计是否合理，需要进行哪些分析，采用什么模型和设置？
```

### 输入

- 已确认的应用设计方案；
- 工况和运行方式；
- 设计目标和优先级；
- 标准、企业规则和专家经验；
- DLAP 能力矩阵、输入 Schema 和已验证案例。

### 职责

- 将设计目标拆成具体分析任务；
- 选择分析顺序和任务依赖；
- 根据工况提出模型开关建议；
- 判断是否需要压力、油膜、温度、流量、摩擦和接触分析；
- 判断是否需要考虑紊流、温度场、热平衡、绝热或给定温度边界；
- 说明每个设置来自标准、企业规则、专家经验还是用户偏好；
- 列出每项分析所需输入；
- 判断哪些设置自动采用、哪些必须用户确认、哪些超出工具能力；
- 发现分析计划与当前工具能力不匹配时阻止执行。

### 工况示例

#### 低速重载

```text
重点：最小油膜、最大压力、接触风险和承载能力。
可能建议：启用接触风险检查，重点检查油膜和比压。
```

#### 高速运行

```text
重点：紊流、摩擦功耗、温升、润滑流量和热平衡。
可能建议：考虑紊流和温度模型。
```

#### 高压顶升或无明显生热

```text
重点：供油压力、油膜形成和承载能力。
可能建议：不启用不必要的温度场模型，但必须说明依据和限制。
```

### 输出

```json
{
  "plan_id": "AP-V1-001",
  "tasks": [
    {
      "task_id": "film",
      "analysis_type": "minimum_film_thickness",
      "enabled": true,
      "reason": "当前设计目标包含最小油膜厚度",
      "evidence_refs": ["design-target:film-thickness"],
      "confirmation": "not_required"
    },
    {
      "task_id": "thermal",
      "analysis_type": "thermal_balance",
      "enabled": true,
      "settings": {
        "boundary": "thermal_equilibrium"
      },
      "reason": "当前高速工况可能存在明显生热",
      "evidence_refs": ["expert-rule:high-speed-thermal-v1"],
      "confirmation": "required"
    }
  ],
  "required_inputs": [
    "load",
    "speed",
    "geometry",
    "lubricant_viscosity",
    "supply_temperature"
  ],
  "execution_order": ["precheck", "film", "thermal", "flow"],
  "unresolved_items": [],
  "requires_user_confirmation": true
}
```

### 与 DLAP 的边界

分析规划 Agent 只输出统一的、语义层面的 `AnalysisPlan`，例如：

```text
启用热平衡分析
采用给定供油温度
考虑紊流
关闭不适用的接触模型
```

它不直接猜测 DLAP 的字段名和命令行参数。DLAP 适配器负责：

```text
AnalysisPlan
→ DLAP 字段映射
→ 单位转换
→ 开关值转换
→ 输入文件生成
```

### 交互与确认

分析规划完成后，必须向用户展示：

- 将执行哪些分析；
- 哪些模型开启或关闭；
- 设置依据；
- 仍然存在的假设；
- 当前工具不能完成的分析。

用户确认后才能进入计算 Agent。

### 禁止事项

- 不直接执行 DLAP；
- 不把未经验证的工具能力当成可用能力；
- 不把滑动轴承经验设置直接迁移到其他轴承类型；
- 不在模型设置不明确时擅自运行。

## 5.5 计算 Agent

### 核心问题

```text
如何把已经确认的分析计划可靠地交给计算程序执行？
```

### 输入

- 当前已确认版本；
- 已确认的 `AnalysisPlan`；
- 计算输入 Schema；
- 已注册的 DLAP 适配器和工具版本。

### 职责

- 检查当前版本和确认状态；
- 执行计算前参数、单位和 Schema 检查；
- 调用确定性的 DLAP 适配器；
- 管理工作目录、超时、取消和日志；
- 保存原始输入、输出和运行证据；
- 解析 DLAP 结果并校验结果 Schema；
- 区分运行成功、计算失败、解析失败和结果不可用；
- 返回统一的 `CalculationResult`。

### 运行链路

```text
DesignState
→ CalculationInput
→ DLAP native input
→ DLAP process/service
→ raw artifacts
→ result parser
→ CalculationResult
```

### 输出

```json
{
  "run_id": "RUN-V1-001",
  "status": "completed",
  "design_version": "V1",
  "adapter": "dlap_journal_v1",
  "tool_version": "verified-version",
  "input_hash": "...",
  "result": {
    "minimum_film_thickness_um": 12.5,
    "maximum_pressure_mpa": 18.2,
    "maximum_temperature_c": 82.0,
    "flow_rate_l_min": 35.0
  },
  "raw_artifacts": [],
  "exit_code": 0,
  "parse_status": "valid",
  "error": null
}
```

### 失败判定

退出码为 0 但输出缺失、结果字段不全、单位无法识别或结果无法解释时，必须判定为失败或不可用，不能进入结果校核通过流程。

### 禁止事项

- 不修改用户已确认的参数；
- 不把工具异常包装成成功；
- 不自行判断油膜、温度或压力是否满足要求；
- 不因为计算失败而自动改变分析开关。

## 5.6 结果校核与解释 Agent

### 核心问题

```text
计算结果是否满足当前设计目标？哪里不满足？下一步可以怎么改？
```

### 输入

- `CalculationResult`；
- 当前设计目标；
- 标准规则和企业规则；
- 分析适用性信息；
- 用户的优先级和约束。

### 职责

- 调用规则引擎执行确定性校核；
- 展示实际值、目标值、单位、来源和版本；
- 将结果分为 `passed`、`failed`、`unknown`；
- 解释失败项和可能相关的设计参数；
- 提出修改方向，但不直接改写状态；
- 区分设计失败、工具失败、规则未知和输入不完整；
- 组织用户确认下一步。

### 规则示例

```json
{
  "rule_id": "JB-FILM-001",
  "name": "最小油膜厚度校核",
  "stage": "post_calculation",
  "inputs": ["minimum_film_thickness", "minimum_film_requirement"],
  "operator": ">=",
  "status_if_unknown": "unknown",
  "source": "待确认标准或企业规则",
  "version": "v1"
}
```

### 输出

```json
{
  "overall_status": "failed",
  "checks": [
    {
      "rule_id": "JB-FILM-001",
      "status": "failed",
      "actual": 1.8,
      "expected": ">= 3.0",
      "unit": "um",
      "evidence_refs": ["run:RUN-V1-001"],
      "message": "最小油膜厚度低于当前设计要求"
    }
  ],
  "unknowns": [],
  "revision_hints": [
    "检查间隙和几何参数",
    "检查润滑油黏度和供油温度",
    "确认载荷和转速输入是否正确"
  ],
  "can_finish": false
}
```

### 禁止事项

- 不由模型自由编造校核阈值；
- 不把 `unknown` 当成通过；
- 不把企业经验隐藏成国家标准；
- 不自动无限次修改参数和重复计算。

## 6. 结果失败后的回路

第一版不增加独立优化 Agent。结果校核后，由总控导师根据失败原因分流。

```text
结果校核与解释 Agent
          ↓
      总控导师 Agent
          ├─ 需求缺失/输入含义不清 → 需求与工况 Agent
          ├─ 分析模型或开关不合适 → 分析规划 Agent
          ├─ DLAP 执行或解析失败 → 计算 Agent
          ├─ 设计指标不满足       → 应用设计 Agent（修改模式）
          └─ 依据冲突/超出范围    → 专家确认
```

### 6.1 应用设计 Agent 的修改模式

当设计结果不满足时，应用设计 Agent 读取：

- 失败校核项；
- 相关敏感参数；
- 用户修改目标；
- 企业限制；
- 既有版本和历史结果。

然后提出一到三个修改方案，例如：

```text
方案 A：调整径向间隙，重点改善油膜厚度；
方案 B：更换润滑油或提高黏度，重点降低接触风险；
方案 C：降低供油量，优先降低成本，但需要重新检查温度。
```

用户选择后创建新版本，不覆盖旧版本。

### 6.2 什么时候再增加优化 Agent

后续需要以下能力时，再增加独立优化 Agent：

- 自动生成多套设计方案；
- 多目标优化温度、流量、成本和变形；
- 自动扫描间隙、流量、黏度等参数；
- 批量调用 DLAP；
- 输出 Pareto 方案集。

优化 Agent 不能替代应用设计 Agent，也不能绕过用户的目标和约束。

## 7. Agent 之间的结构化交接

Agent 不传递长篇自然语言作为工程事实，而传递带版本号和证据引用的结构化对象：

```text
RequirementAssessment
→ DesignProposal
→ AnalysisPlan
→ CalculationRequest
→ CalculationResult
→ ReviewResult
→ RevisionProposal（首期由应用设计 Agent 生成）
```

### 7.1 权限矩阵

| 角色       | 可读取                       | 可提出                       | 可直接写 DesignState | 可执行计算 |
| ---------- | ---------------------------- | ---------------------------- | -------------------- | ---------- |
| 总控导师   | 当前任务和 Agent 结果        | 路由、回复和确认请求         | 否                   | 否         |
| 需求与工况 | 用户消息、参数词典、当前状态 | 事实、问题和缺失项           | 否                   | 否         |
| 应用设计   | 已确认需求、数据库、规则     | 设计方案、参数建议和修改方案 | 否                   | 否         |
| 分析规划   | 已确认设计、工具能力、规则   | 分析任务和模型设置           | 否                   | 否         |
| 计算       | 已确认版本、分析计划         | 运行请求和运行状态           | 否                   | 通过适配器 |
| 结果校核   | 计算结果、规则和目标         | 校核解释和修改方向           | 否                   | 否         |
| 状态服务   | 全部校验后的事件             | 无                           | **唯一写入者**       | 无         |

## 8. 工程服务层

### 8.1 DesignState 和版本服务

保存：

- 设计任务；
- 用户事实及来源；
- 设计方案；
- 分析计划；
- 用户确认；
- 计算记录；
- 校核结果；
- 假设和未知项；
- 版本和修改历史。

### 8.2 问题规划器

Agent 可以提出问题候选，但问题排序由程序完成：

```text
缺失项
→ 阻断性判断
→ 依赖关系
→ 工程风险
→ 用户回答成本
→ 本轮最多三个问题
```

### 8.3 知识检索服务

知识至少分成四类：

```text
标准和手册
专家经验
材料数据库
润滑剂数据库
```

检索结果必须带有来源、版本、适用范围和证据引用。标准原文用于解释和证据；可执行阈值和公式必须经过结构化整理后进入规则库。

### 8.4 规则引擎

规则引擎负责：

- 输入参数检查；
- 设计前适用性检查；
- DLAP 结果校核；
- 标准与企业规则比较；
- `passed / failed / unknown` 判定。

规则来源冲突时，系统必须显示冲突，不允许 Agent 自行覆盖。

### 8.5 DLAP 适配器

适配器负责：

```text
统一 AnalysisPlan
→ DLAP 字段和单位转换
→ 开关映射
→ 输入文件生成
→ 进程/服务调用
→ 输出解析
→ 结果 Schema 校验
```

适配器实现前必须验证：

1. DLAP 模块入口；
2. 输入字段和单位；
3. 默认值和开关含义；
4. 输出字段和单位；
5. 错误语义；
6. 固定算例结果；
7. 超时、取消和工作目录隔离。

在这些内容未验证前，系统只能把 DLAP 结果标记为演示或待验证结果。

## 9. 状态机建议

```text
CREATED
  ↓
REQUIREMENT_CLARIFICATION
  ↓
OPERATING_CONDITION_CONFIRMATION
  ↓
DESIGN_FORMING
  ↓
WAITING_DESIGN_CONFIRMATION
  ↓
ANALYSIS_PLANNING
  ↓
WAITING_ANALYSIS_CONFIRMATION
  ↓
CALCULATION_PRECHECK
  ↓
CALCULATING
  ├─ CALCULATION_FAILED
  └─ RESULT_REVIEW
       ├─ WAITING_FINAL_CONFIRMATION
       ├─ REVISION_PLANNING
       └─ NEED_EXPERT_CONFIRMATION
```

修改后：

```text
REVISION_PLANNING
→ 新版本创建
→ 受影响结果标记 stale
→ DESIGN_FORMING 或 ANALYSIS_PLANNING
```

状态机不负责理解轴承专业知识，只负责阶段顺序、确认门、版本和动作权限。

## 10. 典型交互示例

### 10.1 低速重载

```text
用户：我要设计一个低速重载滑动轴承。

总控：我先确认应用场景、载荷、转速、轴承类型和润滑方式。

需求 Agent：识别为圆柱径向滑动轴承候选，已知低速重载，缺少润滑方式和基本几何。

应用设计 Agent：建议采用动压径向滑动轴承方案，重点确定间隙、供油方式、材料和润滑油黏度。

分析规划 Agent：建议重点分析压力、最小油膜、最大比压和接触风险；温度模型是否启用需要根据生热和工具能力确认。

用户确认分析计划。

计算 Agent：转换 DLAP 参数并执行。

校核 Agent：最小油膜厚度不足，建议调整间隙或润滑油黏度。

应用设计 Agent：提出两个修改方案，等待用户选择。
```

### 10.2 高速工况

```text
需求 Agent：识别为高速连续运行。

应用设计 Agent：将温升、润滑剂黏度变化和供油能力列为重要设计条件。

分析规划 Agent：建议考虑紊流、摩擦功耗和热平衡；显示这些设置的依据并请求确认。

计算 Agent：只执行确认后的设置。
```

## 11. 首期开发顺序

### 阶段 0：确定工具能力

- 选择首期 DLAP 模块；
- 固定圆柱径向滑动轴承黄金案例；
- 确认输入、输出、单位和开关；
- 保存人工认可的预期结果。

### 阶段 1：确定性流程骨架

- `DesignState`；
- 状态机；
- 参数和单位检查；
- 版本与事件；
- 规则结果格式；
- 模拟计算器或固定结果。

### 阶段 2：需求和设计引导

- 需求字段和问题树；
- 需求 Agent；
- 滑动轴承应用设计 Agent；
- 材料和润滑剂查询；
- 方案确认流程。

### 阶段 3：分析规划

- 工况到分析任务的规则；
- 模型开关建议；
- 分析计划确认；
- 工具能力检查。

### 阶段 4：计算接入

- DLAP 适配器；
- 参数转换；
- 输入输出保存；
- 异常和输出缺失处理；
- 固定案例复现测试。

### 阶段 5：结果校核与修改

- 最小油膜、压力、温度等规则；
- `passed / failed / unknown`；
- 失败解释；
- 应用设计 Agent 修改模式；
- 新版本重算。

## 12. 首期验收场景

至少包括：

1. 用户只输入一句“设计一个低速重载滑动轴承”，系统能逐步引导；
2. 载荷、转速或单位缺失时，系统阻止不完整计算；
3. 用户不清楚润滑油参数时，系统解释数据用途并提供未知/建议/专家确认选项；
4. 低速重载工况触发油膜、压力和接触风险分析建议；
5. 高速工况触发紊流、温升或热平衡分析建议；
6. 高压顶升工况不会无理由启用温度场模型；
7. 用户能看到每个分析开关及其理由，并在计算前确认；
8. DLAP 退出码为 0 但输出缺失时判定计算失败；
9. 计算结果低于油膜或温度要求时，系统能解释失败项；
10. 用户修改间隙、流量或润滑油后创建新版本并重新分析；
11. 规则依据不明确时返回 `unknown`，不能报告通过；
12. 同一版本、同一输入和同一规则集能够复现相同结果。

## 13. 需要导师确认的范围

以下内容在实现前需要确认，但不影响框架成立：

1. 首期黄金路径采用圆柱径向动压轴承，还是同时加入静压轴承；
2. 首期正式校核至少包括哪些指标：油膜、压力、温度、流量、摩擦功耗中的哪些；
3. 采用哪些 ISO/国标、手册和企业经验作为第一版规则来源；
4. 哪些 DLAP 模型开关可以自动建议，哪些必须每次由用户确认；
5. 第一版报告达到教学演示、方案比较还是工程初步审核的证据等级。

## 14. 总结性架构

```text
用户
 ↓
总控导师 Agent
 ├─ 需求与工况 Agent
 ├─ 滑动轴承应用设计 Agent
 ├─ 分析规划 Agent
 ├─ 计算 Agent → DLAP 适配器 → DLAP
 └─ 结果校核与解释 Agent
          ↓
   失败后按原因回到正确阶段
          ↓
   应用设计 Agent 修改模式
          ↓
        新版本重算
```

第一版的核心创新和工程价值不在于 Agent 数量，而在于：

```text
把滑动轴承应用设计过程结构化，
让系统根据工况引导分析选择，
让计算设置有依据、可确认，
让结果能够校核、解释和迭代复现。
```
